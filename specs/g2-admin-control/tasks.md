# Tasks: g2-admin-control

**Input**: `specs/g2-admin-control/spec.md`, `specs/g2-admin-control/plan.md`
**Traceability rule**: every task cites at least one assigned requirement
(FR-ADM-001/003/007) or an acceptance criterion of those requirements
(AC-014, AC-063, and the shared G2 ACs AC-010…013, AC-060…062, AC-260…264).
Requirement IDs not assigned to this package never appear here.

Format: `- [ ] T### [P?]` — **[P]** = parallelizable with its neighbors (disjoint files).
A PRODUCT task that must stay serial carries exactly one
`[serial-reason: SEMANTIC_DEPENDENCY|SHARED_FILE|ORDERED_MIGRATION|SHARED_INVARIANT|COORDINATOR_BOUNDARY|SAFETY_SERIALIZATION]`
marker (2026-09-08 maintainer directive; the parallelism audit refuses an
unjustified serial plan). Test-owned work carries `[executor: TEST]` and is
routed to the test-author lanes; implementation-dispatched product tasks
NEVER carry test/fixture/spec writes (2026-09-07 ownership admission law —
the graph builder refuses such plans before any provider spend).
Tests are mandatory per PRD evidence rules: positive AND negative/failure-path
specs for every acceptance criterion this package touches (AC-010…014,
AC-060…063, AC-260…264). All 14 of those ACs are SHARED with other
families whose base `tests/acceptance` / `tests/negative` files already
exist on `main` (AC-014/AC-063 currently trace to FR-WF-004/FR-WF-008);
this package adds the admin-scoped assertions additively and preserves the
landed family assertions (it never re-homes them).

Plan-sanctioned scope exceptions recorded per the milestone plan-level
decisions (1 and 2) and ADR-0019/ADR-0022 duty, named by exact path:
`packages/persistence/src/migrator.ts` (family-list extension with `adm`,
product-owned T007), `packages/persistence/src/generated/schema.ts`
(ADR-001 mirror catch-up, product-owned T008),
`packages/persistence/test/migrator.spec.ts` (central expected-script
registry, test-owned T009), `tests/telemetry-catalog.spec.ts` (central
telemetry parity suite, test-owned T029), and `docs/generated/**` —
concretely `docs/generated/adm-surfaces.json` — regenerated by the central
generator because `docs/generated/**` is deliberately outside the package
writeScopes (product-owned T030).

Staging order mirrors PRD §28/§25.11/§69 and the plan's architecture
decisions: admin vocabularies and shared schemas first, then persistence
(`adm` schema), then the high-impact action guard and fail-closed kill
switches, then the provider-call-free overview read model, then the
immutable-version configuration control plane, then the HTTP admin surface,
then the dependency-light dashboard, then telemetry and the admin-scoped AC
suites, then cross-artifact convergence.

## Phase 3 — High-impact action guard and fail-closed kill switches

- [ ] T011 [P] Create `apps/api/src/routes/admin/control-safety.ts`: the
      §35.1 high-impact action guard used by every control and kill-switch
      action — fresh phishing-resistant step-up, exact authorization via the

      non-empty reason, and audit; TOTP-only authentication is refused; each

      model. Traces: FR-ADM-003, FR-ADM-007, AC-014, AC-063, AC-262.
- [ ] T012 [P] Create `apps/api/src/routes/admin/kill-switches.ts`: the
      fail-closed resolver over `adm.kill_switch_states`/`adm.kill_switch_events`
      for the six §28.13 kinds; missing/unreadable/expired/unknown state
      resolves to the closed state; `assertCallAllowed(kind, scope)` is the
      single gate every admin/control downstream call consults before
      constructing a provider, model, notification, or MCP-client call;
      `EMERGENCY_READ_ONLY_MODE` closed permits reads and refuses every
      write/automation path; engage/disengage appends state + event with no
      UPDATE, no auto-reactivation, and no fail-open branch; enforcement at
      foreign call sites is exposed as a port seam (plan D4) rather than a
      foreign-package write. Traces: FR-ADM-007, AC-061, AC-262.
- [ ] T013 [executor: TEST] [P] Unit tests for T011/T012 on PGlite: all six
      switches default closed when no state row exists and when a state read
      fails; an ENGAGED switch makes `assertCallAllowed` refuse every gated
      kind; `EMERGENCY_READ_ONLY_MODE` allows reads and refuses writes;
      a stale step-up, missing CSRF, missing idempotency key, missing reason,
      or TOTP-only proof is refused and audited; a replayed engage collapses on
      the idempotency key and changes nothing; there is no automatic
      reactivation. Traces: FR-ADM-007, AC-014, AC-061, AC-262.

## Phase 5 — Immutable-version configuration and schedule control plane

- [ ] T017 [P] Create `apps/api/src/routes/admin/configuration-control.ts`:
      the §28.3–§28.5 control plane over `adm.configuration_versions` and
      `adm.resolved_config_previews` — edit always creates a new immutable
      version; VALIDATE/APPROVE/ACTIVATE/DEPRECATE/ROLL_BACK follow the
      lifecycle with ACTIVATE requiring a validated+approved version and, for
      schedules, a fresh §33.6 forecast for the exact version; ROLL_BACK

      to `@foresift/quota-forecast`/`@foresift/capacity-planner`; cron,
      timezone, precedence, forecast, run/dead-letter, and gate logic are never
      re-derived. Traces: FR-ADM-003, AC-010, AC-011, AC-012, AC-013, AC-014,
      AC-063.
